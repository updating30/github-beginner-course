第1回 ／ GitHub Desktop 入門

GitHubって何？
タイムマシンを手に入れよう

🎯 GitHubとGitの違いが説明できる
🎯 GitHub Desktopで最初のリポジトリを作れる
🎯 「コミット（保存スタンプ）」の操作ができる
💼 ビジネスでの例え話：プロジェクト金庫と変更台帳

Gitを理解するには「会社の書類管理」に例えるのが一番です。

【従来の管理方法】 📁 企画書_v1.docx 📁 企画書_v2_山田修正.docx 📁 企画書_v3_最終.docx 📁 企画書_v3_最終_本当に最終.docx ← 誰もが経験あり 【GitHubを使った管理】 📦 企画書プロジェクト（リポジトリ＝プロジェクト金庫） ├── 🔖 2024/04/01 田中：初稿作成 ├── 🔖 2024/04/05 山田：第2章を修正 └── 🔖 2024/04/10 鈴木：最終確認済み

リポジトリ＝プロジェクトごとの「金庫」（すべての変更履歴が入っている）
コミット＝「保存スタンプ」（いつ・誰が・何を変えたかが自動記録される）

💡 タイムマシンのイメージ：コミットを積み重ねることで「1ヶ月前のあの時点」に1クリックで戻れます。ファイルを誤って上書きしても、もう怖くありません。
具体的な操作手順
1
GitHub Desktop のインストール
▲
  1. ブラウザで desktop.github.com を開く
  2. 「Download for Windows」をクリックしてインストール
  3. GitHubアカウントでサインイン（アカウントがなければ無料で作成）
2
最初のリポジトリを作る
▼
  1. GitHub Desktop を起動
  2. 左上の「File」→「New Repository」をクリック
  3. Name：my-first-project（プロジェクト名）
  4. Local Path：保存場所（例：デスクトップ）
  5. 「Create Repository」ボタンをクリック
3
ファイルを追加してコミットする
▼
  1. エクスプローラーで作成されたフォルダを開く
  2. 中に README.txt を作成し、自己紹介文を書いて保存
  3. GitHub Desktop に戻ると、変更が自動で検出される
  4. 左下の「Summary」欄に「最初のファイルを追加」と入力
  5. 「Commit to main」ボタンをクリック → 保存スタンプ完成！
4
変更して再度コミット
▼
  1. README.txt を開いて文章を書き換えて保存
  2. GitHub Desktop で変更内容が表示される（🔴削除、🟢追加）
  3. Summary に「自己紹介を更新」と入力してコミット
5
タイムマシンを体験する（過去に戻る）
▼
  1. 左側の「History」タブをクリック
  2. コミット一覧が表示される
  3. 右クリック → 「Revert this Commit」で元に戻せることを確認
🏆 この回を終えると…業務のここが楽になる
✅ファイル名に日付やバージョンを付ける必要がなくなる
✅「誰がいつ何を変えたか」が自動的に記録される
✅誤って上書きしても、以前の状態に1クリックで戻せる
✅「最新版はどれ？」という混乱が永遠になくなる

第2回 ／ ブランチ入門

安全に試作する
「実験ルーム」を作ろう

🎯ブランチの概念を理解する
🎯GitHub Desktop で新しいブランチを作れる
🎯試作をメインに「合流」（マージ）できる
🏭 ビジネスでの例え話：本番を汚さない試作場

工場の生産ラインに例えてみましょう。

【ブランチなしの危険な状態】 本番ライン ─────── 実験中（失敗したら大惨事） 【ブランチありの安全な状態】 本番ライン（main）────────────────────► 完成品出荷 ↘ ↗ 試作ライン（branch）← ここで自由に実験

ブランチ＝本番（main）から切り離した「試作場」「下書きスペース」

💡 稟議書の例え：決裁済みの書類はそのまま保管しておき、修正案は「別のコピー」で作業するイメージです。OKが出たら本番に反映する。
具体的な操作手順
1
新しいブランチを作る
▲
  1. GitHub Desktop 上部の「Current Branch」をクリック
  2. 「New Branch」をクリック
  3. 名前を入力：feature/new-content（「試作機能」の意味）
  4. 「Create Branch」をクリック
2
ブランチ上で自由に編集する
▼
  1. README.txt を開いて大きく変更（思い切り書き換えてOK！）
  2. GitHub Desktop でコミットする
  3. 上部のブランチ名が feature/new-content になっていることを確認
3
main に戻って内容を比較する
▼
  1. 「Current Branch」→ main に切り替える
  2. README.txt を開くと、変更前の内容に戻っていることを確認
  3. ブランチを切り替えるだけで内容が変わる感覚をつかむ
4
ブランチを main にマージする
▼
  1. 「Current Branch」で main を選択した状態で
  2. 上部メニュー「Branch」→「Merge into Current Branch」
  3. feature/new-content を選んで「Create a merge commit」
  4. main に変更内容が取り込まれる 🎉
🏆 この回を終えると…業務のここが楽になる
✅本番ファイルを壊す心配なく自由に試せる
✅複数のアイデアを並行して試作できる
✅「やっぱり元に戻したい」がブランチを消すだけで実現
✅チームで同時並行作業が可能になる

第3回 ／ プルリクエスト入門

チームに共有・
上司に確認を求める

🎯リポジトリを GitHub.com にアップロードできる
🎯プルリクエスト（PR）を作成・コメントできる
🎯チームのレビューフローがわかる
📋 ビジネスでの例え話：デジタル稟議フロー

プルリクエストは、デジタル版の「上司への確認依頼」です。

【従来の確認フロー】 部下：「修正版できました！」→ メールに添付 → 上司が確認 → 口頭でOK （どこが変わったか分かりにくい、記録も残りにくい） 【GitHubのフロー】 部下：プルリクエストを作成（変更箇所が自動でハイライト表示） 上司：コメント欄で質問・指摘（記録がすべて残る） 部下：修正してコミット 上司：「Approve（承認）」ボタンを押す → main ブランチに自動マージ ✅
具体的な操作手順
1
ローカルのリポジトリをクラウドに公開する
▲
  1. GitHub Desktop で「Publish repository」ボタンをクリック
  2. 「Keep this code private」にチェック（非公開にする場合）
  3. 「Publish Repository」をクリック
  4. ブラウザで github.com を開くと、リポジトリが表示される
2
新しいブランチで変更し、プッシュする
▼
  1. 新しいブランチを作成（例：feature/update-readme）
  2. ファイルを変更してコミット
  3. GitHub Desktop の「Push origin」ボタンをクリック（クラウドに送信）
3
プルリクエストを作成する
▼
  1. ブラウザで GitHub を開くと「Compare & pull request」ボタンが表示される
  2. クリックして PR 作成画面へ
  3. タイトルに変更内容を入力（例：「README に自己紹介を追加しました」）
  4. 本文に確認してほしいポイントを記入
  5. 「Create pull request」ボタンをクリック
4
レビューする側の操作
▼
  1. PR ページの「Files changed」タブで変更内容を確認
  2. 気になる行にカーソルを合わせると「+」ボタンが出る
  3. クリックしてコメントを記入できる
  4. 「Review changes」→「Approve」で承認
5
マージして完了
▼
  1. 「Merge pull request」ボタンをクリック
  2. main ブランチに変更が取り込まれる 🎉
🏆 この回を終えると…業務のここが楽になる
✅「どこを変えたか」が一目瞭然（差分表示）
✅確認・承認のやりとりが記録として永久に残る
✅メールの添付ファイルが不要になる
✅「あの時なぜこうしたか」を後から追跡できる

Python コードを

🎯VS Code を使って Python ファイルを管理できる

📦 excel-automation（リポジトリ） ├── 📄 monthly_report.py ← 月次レポート自動生成 ├── 📄 data_cleaner.py ← データ整形スクリプト └── 📄 README.md ← 使い方の説明書 変更履歴： 🔖 2024/04 田中：月次レポートを自動化 🔖 2024/05 山田：商品マスタ対応を追加 🔖 2024/06 田中：バグ修正（消費税計算を修正）← 後から追跡可能！
具体的な操作手順
1
VS Code のセットアップ
▲
  1. code.visualstudio.com から VS Code をインストール
  2. VS Code を起動 → 左側の「ソース管理」アイコン（分岐マーク）を確認
  3. 第1回で作ったリポジトリのフォルダを VS Code で開く
2
Python ファイルを作って VS Code 内でコミット
▼
  1. VS Code で新しいファイル hello_excel.py を作成
  2. 以下を入力して保存：
import openpyxl

# Excelファイルを作成して保存
wb = openpyxl.Workbook()
ws = wb.active
ws['A1'] = 'GitHubで管理された自動化スクリプト'
wb.save('output.xlsx')
print('Excelファイルを作成しました')
  1. 左の「ソース管理」アイコンをクリック
  2. 変更ファイルの右にある「＋」をクリックしてステージング
  3. 上部の入力欄にコミットメッセージを入力
  4. チェックマーク（✔）をクリックしてコミット完了
3
VS Code のターミナルで実行する
▼
  1. VS Code で「ターミナル」→「新しいターミナル」
  2. pip install openpyxl を実行（初回のみ）
  3. python hello_excel.py を実行
  4. output.xlsx が生成されることを確認
4
.gitignore で不要ファイルを除外する
▼
  1. ルートフォルダに .gitignore ファイルを作成
  2. 以下を記入：
output.xlsx
__pycache__/
*.pyc
.env

✅同僚に「共有して」と言われたら URL を渡すだけ

第5回 ／ GitHub Copilot 入門

AI と一緒にコードを書く
現代の開発スタイル

🎯GitHub Copilot の基本的な使い方を理解する
🎯AI の提案を採用・修正しながらコードを書ける
🎯Copilot × GitHub を使ったワークフローを身につける
🤖 ビジネスでの例え話：優秀な新入社員との共同作業

GitHub Copilot は「コードを書ける優秀な新入社員」と思ってください。

あなた（指示を出す人）：「月次売上をグラフ化するコードを書いて」 Copilot（実装する人）：「こういうコードはいかがでしょう？」→ 提案を表示 あなた：内容を確認して 採用 / 修正 / 却下
💡 重要：AIが書いたコードを「理解して採用する」こと。丸投げではなく、あなたが意思決定者です。コードを書く量を減らし、業務課題を解くことに集中できます。
具体的な操作手順
1
GitHub Copilot の準備
▲
  1. github.com → 右上のアイコン → 「Settings」
  2. 「GitHub Copilot」→ 有効化（まずは無料プラン「Copilot Free」で試せます）
  3. VS Code の「拡張機能」で「GitHub Copilot」を検索してインストール
2
Copilot にコードを書いてもらう
▼
  1. VS Code で新しいファイル sales_report.py を作成
  2. 以下のコメントを書くと、Copilot が自動的に提案を出す：
# Excelファイルから売上データを読み込み、月別集計をして棒グラフを作成する
  1. Tab キーで提案を採用、Esc で却下
  2. 生成されたコードを読んで理解する（わからない部分は Copilot に聞く）
3
Copilot Chat で日本語で対話する
▼
  1. VS Code で Ctrl + Shift + I（Copilot Chat を開く）
  2. 日本語で質問できる：
    「このコードの処理内容を日本語で説明して」
    「エラーが出ています：[エラー文]。原因と修正方法を教えて」
    「もっとシンプルなコードに書き直して」
4
完成したコードを GitHub に保存する
▼
  1. コードが動作したら VS Code のソース管理でコミット
  2. コミットメッセージ例：Copilot活用：月次売上グラフ生成スクリプトを追加
  3. GitHub にプッシュして保存完了
5
チームへの共有フロー（総仕上げ）
▼
  1. ブランチを切る（feature/sales-graph）
  2. Copilot と一緒にコードを書く
  3. 動作確認後、コミット＆プッシュ
  4. プルリクエストを作成
  5. チームがレビュー・承認
  6. main にマージ → 業務で使える！🎉
🏆 この回を終えると…業務のここが楽になる
✅プログラミング経験が少なくても実用的なコードが書ける
✅AIが下書きを書き、あなたが意思決定するという分業スタイル
✅コードの意味を AI に説明してもらいながら学べる
✅「コードを書く」から「業務課題を解く」に集中できる

Glossary

用語集：ビジネス言葉で理解する

リポジトリ プロジェクトごとの「金庫」。すべての変更履歴が入っている。
コミット 変更履歴の「保存スタンプ」。いつ・誰が・何を変えたか自動記録。
ブランチ 本番を汚さない「試作場・下書きスペース」。
マージ 試作品を本番ラインに組み込む作業。
プルリクエスト デジタル上での「確認依頼・稟議書」。コメントで記録が残る。
クローン リモートの金庫を手元にコピーする。
プッシュ 手元の変更をクラウドに送信する（バックアップと共有を同時に）。
プル クラウドの最新版を手元に取得する。
.gitignore 管理対象外ファイルのリスト。「この書類は金庫に入れなくていい」の設定。
